## Executive Summary

The AWS TerraGoat corpus is an intentionally vulnerable Terraform codebase structured around the OWASP Top 10. It demonstrates every major class of AWS infrastructure security failure: wildcard IAM policies, world-open security groups, unencrypted storage and databases, missing IMDSv2 enforcement, absent CloudTrail multi-region logging, and hardcoded credentials in HCL. Each file maps to a specific OWASP category with documented expected detections.

**Strengths:** Provider version constraints are present with upper bounds (`~> 5.50` for AWS, `~> 3.2` for Null); `aws_db_instance.public_db` has `deletion_protection = true` and `storage_encrypted = true`; `aws_db_instance.no_backups` has `deletion_protection = true` and `storage_encrypted = true`; the `db_password` variable is correctly marked `sensitive = true`.

- **[SEC-AWS-SG-001#1] Security group allows SSH from 0.0.0.0/0** — 05_security_misconfiguration.tf:34 | Blast: environment | CIS: n/a | Effort: Small | Status: VERIFIED
  Description: `aws_security_group.ssh_open` allows TCP port 22 ingress from `0.0.0.0/0`. Every instance attached to this SG is SSH-reachable from the internet. Brute-force SSH attacks are the #1 attack vector on AWS EC2 instances. The catalogue escalation rule promotes this from HIGH to CRITICAL because port 22 is involved.
  Recommendation: Restrict `cidr_blocks` to corporate CIDR blocks. Use AWS Systems Manager Session Manager or a bastion host instead of direct SSH access from the internet.
  Verification: `aws ec2 describe-security-groups --group-ids <sg-id> --query 'SecurityGroups[0].IpPermissions[?FromPort==\`22\`].IpRanges'` does not contain `0.0.0.0/0`.
