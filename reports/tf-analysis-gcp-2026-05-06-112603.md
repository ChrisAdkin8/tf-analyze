## Executive Summary

The GCP TerraGoat corpus is an intentionally vulnerable Terraform codebase structured around the OWASP Top 10. It demonstrates every major class of GCP infrastructure security failure: public IAM bindings, world-open firewalls, missing encryption rotation, unprotected stateful resources, and absent audit logging. ## 1. Security Posture

### CRITICAL

- **[SEC-IAM-002#1] Public IAM binding — allUsers** — 01_broken_access_control.tf:38 | Blast: infrastructure-wide | CIS: 5.1 | Effort: Small | Status: VERIFIED
  Description: `google_storage_bucket_iam_member.public_objects` grants `roles/storage.objectViewer` to `allUsers`, exposing every object in `demo-public-bucket` to anonymous internet reads. Any sensitive data in the bucket is immediately exfiltrable.
  Recommendation: Remove the `allUsers` binding. If external read access is required, use signed URLs or a CDN with IAM-gated origin.
  Verification: `gcloud storage buckets get-iam-policy gs://demo-public-bucket --format='value(bindings)' | grep allUsers` returns nothing.

- **[SEC-NETWORK-001#1] SSH exposed to 0.0.0.0/0** — 05_security_misconfiguration.tf:63 | Blast: environment | CIS: 3.6 | Effort: Small | Status: VERIFIED
  Description: `google_compute_firewall.ssh_open` allows TCP port 22 from `0.0.0.0/0`. Every VM on the `default` network is SSH-reachable from the internet. Brute-force SSH attacks are the #1 attack vector on GCP compute instances.
  Recommendation: Restrict `source_ranges` to corporate CIDR blocks or use IAP tunneling (`35.235.240.0/20`) instead.
  Verification: `gcloud compute firewall-rules describe demo-ssh-open --format='value(sourceRanges)'` does not contain `0.0.0.0/0`.
